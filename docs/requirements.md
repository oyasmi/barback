## 1. 定位

> 用 supervisor 的语义管理 macOS 上的后台服务与常用命令，操作入口在状态栏。

**命名**：Barback 意为吧台助理——在后台备货、清理、维持吧台运转；同时双关 macOS 的 **Menu Bar**。

**目标用户**：在自己 Mac 上常年跑若干后台进程（本地服务、模型推理、隧道、同步守护）的个人开发者。

**要解决的问题**：

| 现状 | 痛点 |
| --- | --- |
| Homebrew supervisord + Web UI | 语义好用，交互难用：重启一个服务要开终端敲命令或开浏览器点 2005 年风格的表格；服务挂了无感知；看日志要记路径；INI 手写易错；Python 常驻不是 macOS 公民 |
| 自研 cmd_mgr | 有 GUI，但没有 autostart/autorestart/startsecs 等监管语义；配置与操作挤在同一个窗口，高频操作路径长 |

**产品原则**：

1. **操作零成本**——看状态、重启、看日志、跑一次性命令，都在状态栏两次点击内完成。
2. **配置与操作分离**——低频的"定义"在独立窗口，高频的"操控"在状态栏菜单。这是相对 cmd_mgr 的核心改进。
3. **语义向 supervisor 看齐**——同名字段同义，心智模型可直接迁移。
4. **简单优先**——单进程、单一数据库、无守护进程、无 IPC。能少一个活动部件就少一个。
5. **常驻即克制**——空闲时接近零 CPU，不做周期性轮询。

## 2. 范围

### 2.1 v1.0 做

- **两类被管对象**：**服务**（长期运行，带监管语义）与 **一次性命令**（手动触发、跑完即止、留执行历史）。
- 状态栏左键面板：服务与一次性命令的列表、状态、逐项操作、全局操作。
- 状态栏右键菜单：Barback 自身功能（配置窗口、偏好、日志、版本、退出）。
- 独立配置窗口：唯一的配置入口，两类对象的增删改查与字段校验。
- 日志：子进程输出落盘、按大小轮转、内置查看器（跟随 + 搜索）；一次性命令按次保留输出。
- 执行历史：一次性命令的每次运行记录（时间、耗时、退出码、输出）。
- 从 supervisor 迁移：**粘贴 INI 文本**导入。
- 事件记录与系统通知。
- 开机自启（登录项）。

### 2.2 v1.0 不做

| 不做 | 原因 |
| --- | --- |
| 独立守护进程 / LaunchAgent 托管 | 采用单进程架构：Barback 退出，被管进程一并退出（§3.3 语义约定） |
| 配置文件手工编辑 | 配置存 SQLite，**只能通过 GUI 修改**；不提供文本配置格式、不做文件监听 |
| root / 系统级服务 | 需要特权助手与授权弹窗，与"简单"冲突；实际需求是用户级 |
| 远程管理 / Web UI / 多机 | 与"本机个人工具"定位冲突 |
| 定时任务（cron 语义） | 那是 launchd 的地盘；一次性命令为手动触发 |
| 程序间依赖图 | 先用 priority 排序覆盖绝大多数场景 |
| 交互式进程（需 TTY 输入） | 子进程不分配 TTY |
| 自动更新 | v1 仅"检查更新并提示" |
| 命令行客户端 | 单进程架构下需要额外 IPC，与"简单"冲突 |

### 2.3 后续候选（不承诺）

v1.1：健康检查探针（HTTP/TCP/命令）、RSS 超限自动重启、一次性命令的参数化输入。
v2：依赖编排、Keychain 保管敏感变量、配置多 Profile。

## 3. 概念模型

```
Program（被管理对象）
 ├─ kind = service   长期服务：autostart / autorestart / 退避 / 停止序列
 └─ kind = oneshot   一次性命令：手动触发 / 超时 / 执行历史
```

### 3.1 服务状态

与 supervisor 同名同义：

| 状态 | 含义 | 界面文案 |
| --- | --- | --- |
| `STOPPED` | 未运行（从未启动或被显式停止） | 已停止 |
| `STARTING` | 已启动，未满足存活门槛 `startSeconds` | 启动中 |
| `RUNNING` | 稳定运行 | 运行中 |
| `BACKOFF` | 启动失败，退避等待重试 | 重试中 n/N |
| `STOPPING` | 已发停止信号，等待退出 | 停止中 |
| `EXITED` | 自行退出且不再重启 | 已退出 (码) |
| `FATAL` | 重试耗尽，放弃 | 启动失败 ⚠ |

### 3.2 一次性命令状态

`IDLE`（空闲）→ `RUNNING`（执行中）→ `SUCCEEDED` / `FAILED(码)` / `TIMEOUT` / `CANCELLED`。终态仅用于展示"上次结果"，下次触发回到 `RUNNING`。

### 3.3 生命周期约定（重要）

**Barback 退出 = 所有被管进程退出。** 退出时按 priority 降序执行停止序列；正在跑的一次性命令一并终止（有确认提示）。这是单进程架构的明确语义，用户在退出确认框中会被告知。

## 4. 用户路径

**UJ-1 首次启动**：双击打开 → 一次性欢迎窗口说明"入口在状态栏、无 Dock 图标" → 询问是否注册开机自启与通知权限 → 引导添加第一个程序或粘贴导入 supervisor 配置 → 关闭窗口，此后只剩状态栏图标。

**UJ-2 左键面板（最高频）**：点图标 → 面板分两节（服务 / 一次性命令），每行显示状态点 + 名称 + 状态徽标 + PID/运行时长/CPU/内存 → 直接点行上的「停止」/「重启」/「运行」。全程两步、无输入、无二级菜单。要求点击到面板可见 < 100 ms。

**UJ-3 右键菜单**：Barback 自身功能，与左键面板内容完全不重叠——配置窗口、执行历史、事件日志、日志目录、偏好设置、开机自启开关、粘贴导入、检查更新、关于、退出。

**UJ-4 配置**：右键「打开配置窗口」或某程序的「编辑配置」→ 左侧列表 + 右侧分区表单 → 先选类型（服务 / 一次性命令），表单随之切换字段 → 新手只填"名称 + 命令"即可，其余字段有与 supervisor 一致的默认值 → 高级字段折叠 → 保存时就地校验（不弹窗）→ 运行中的服务若改了运行时字段，提供「保存并重启」。

**UJ-5 看日志**：左键面板 → 程序行的日志按钮 → 独立窗口，默认跟随末尾，支持搜索高亮、暂停跟随、清空、在 Finder 中显示。关窗即停止监听。

**UJ-6 跑一次性命令**：左键面板 → 行上的「运行」（标记为危险的命令先弹确认）→ 图标短暂进入忙态 → 完成后发通知（成功/失败 + 耗时）→ 再次打开面板可见"上次 今天 10:22 · 耗时 3.4 秒 · 共 27 次"，行上直达「查看输出」「执行历史」。

**UJ-7 迁移**：右键「从 supervisor 粘贴导入」→ 粘贴一段或多段 `[program:x]` INI 文本 → 解析后展示映射预览表（可导入字段 / 无法映射字段及原因）→ 逐条勾选 → 导入，**一律以 autostart=false 落地**，并提示先停用 supervisord 再启动，避免抢占端口。

**UJ-8 异常**：

| 场景 | 期望 |
| --- | --- |
| 服务启动 2 秒即退出（`startSeconds=5`） | 判失败 → BACKOFF → 退避重试 → 重试耗尽 → FATAL，图标变警示态并通知 |
| 运行数天后崩溃（`autorestart=unexpected`，码非 0） | 自动重启并记录事件；连续崩溃触发退避；通知按 10 分钟去抖 |
| 正常退出码 0（`unexpected`） | 进入 EXITED，不重启，不通知 |
| 用户手动停止 | STOPPED，本次会话内绝不自动重启；但下次启动 Barback 时仍按 autostart 拉起 |
| 睡眠唤醒 | 唤醒后核对所有 PID，修正状态漂移 |
| Barback 自身崩溃 | 下次启动时检测上次遗留的进程，重新接管（不重复启动、不留失管孤儿） |
| 磁盘写满 | 记录 + 通知 + 菜单标注，**不因日志问题杀死业务进程** |
| 一次性命令超时 | 按停止序列终止，记为 TIMEOUT 并通知 |

## 5. 功能需求

优先级 M=必须 / S=应该 / C=可以。

### FR-CFG 配置管理

| ID | P | 需求 |
| --- | --- | --- |
| CFG-1 | M | 创建/编辑/复制/删除/启停用 Program；名称唯一，`[A-Za-z0-9._-]{1,64}` |
| CFG-2 | M | 配置存 SQLite 单库；**GUI 是唯一入口**，不支持外部编辑 |
| CFG-3 | M | 两种 kind（service / oneshot）字段集不同，表单随类型切换；已创建对象不可改 kind（可复制为另一类型） |
| CFG-4 | M | 保存前校验：名称合法且唯一、命令可解析且首个 token 可执行、工作目录存在、日志目录可写、数值范围 |
| CFG-5 | M | 运行中的服务修改运行时字段（命令/目录/环境/日志路径）→ 标记"需重启生效"，提供「保存并重启」；非运行时字段（autostart/autorestart/priority/分组/备注/轮转参数）即时生效 |
| CFG-6 | M | 从粘贴的 supervisor INI 文本导入，含映射预览与不可映射说明；非破坏性（不读写任何 supervisor 文件） |
| CFG-7 | S | 导出全部配置为 JSON、导入同格式（备份/换机用，非日常编辑手段） |
| CFG-8 | S | 分组：菜单按组分节，支持"启动本组/停止本组" |

### FR-SVC 服务监管

| ID | P | 需求 |
| --- | --- | --- |
| SVC-1 | M | 实现 §3.1 的 7 态状态机，语义与 supervisor 一致 |
| SVC-2 | M | `autostart`：Barback 每次启动时**无条件**按 priority 升序串行拉起，不记忆上次是否被手动停止 |
| SVC-3 | M | `startSeconds`：存活满该秒数才判 RUNNING；未满即退出算一次启动失败（0 = spawn 成功即 RUNNING） |
| SVC-4 | M | `startRetries`：失败重试上限，耗尽进 FATAL；FATAL 可手动清除并重启 |
| SVC-5 | M | `autorestart` 三档：never / unexpected（退出码不在 `exitCodes` 内才重启）/ always |
| SVC-6 | M | 指数退避（base/max/抖动可配），UI 显示剩余等待秒数；崩溃风暴保护：滑动窗口内重启超阈值强制 FATAL |
| SVC-7 | M | 停止序列：`stopSignal`（默认 TERM）→ 等 `stopWaitSeconds`（默认 10s）→ SIGKILL |
| SVC-8 | M | `stopAsGroup` / `killAsGroup`：信号发给整个进程组，清理 shell 包装脚本的子孙进程 |
| SVC-9 | M | 单项 start/stop/restart；全局 start all / stop all / restart all |
| SVC-10 | M | 环境变量：登录 shell 环境快照 + 程序自定义变量，注入 `BARBACK_PROGRAM_NAME` |
| SVC-11 | M | Barback 崩溃后重启时接管仍存活的进程（PID + 启动时刻双因子校验），不重复启动 |

### FR-ONE 一次性命令

| ID | P | 需求 |
| --- | --- | --- |
| ONE-1 | M | 菜单中一键触发执行；执行中该项禁止重复触发（无条件串行，不支持并发实例，ex-F12） |
| ONE-2 | M | 可中止正在执行的命令（走与服务相同的停止序列） |
| ONE-3 | M | 超时 `timeoutSeconds`（默认 0 = 不限）；超时按停止序列终止并记为 TIMEOUT |
| ONE-4 | M | 每次执行生成一条运行记录：触发时间、耗时、退出码/信号、结果、独立输出文件 |
| ONE-5 | M | 执行历史窗口：按命令筛选、查看任一次的输出、重跑、清理历史；每命令保留最近 N 次（默认 50，可配） |
| ONE-6 | M | 执行完成发系统通知（成功/失败/超时 + 耗时），可分级关闭 |
| ONE-7 | S | `confirmBeforeRun`：标记为危险的命令执行前弹确认 |
| ONE-8 | S | 面板行直接展示"上次结果 + 时间 + 耗时 + 累计次数"，并就地提供「查看本次输出」 |
| ONE-9 | C | 执行时在状态栏图标上以忙态指示当前有命令在跑 |

## 6. 非功能需求

### 资源（核心指标）

| 指标 | 目标 | 上限 |
| --- | --- | --- |
| 常驻 RSS（管理 10 项，菜单未开，无窗口） | ≤ 70 MB | 130 MB |
| 空闲 CPU（无事件、菜单未开） | ≈ 0%，**无周期性轮询** | 0.3% |
| 日志吞吐带来的额外 CPU | ≈ 0（子进程直写文件，主程序不中转日志数据） | — |
| 安装体积 | ≤ 20 MB | 50 MB |
| 电源断言 | 不持有、不阻止睡眠 | — |
| 24 小时内存增长 | < 2% | 10% |

### 稳定性

| ID | 需求 |
| --- | --- |
| REL-1 | 单个被管进程的异常（崩溃、狂输出、吃内存、僵尸）不得影响 Barback 或其他被管进程 |
| REL-2 | 监管逻辑与 UI 代码解耦并运行在独立队列，UI 卡顿不影响监管；监管核心不 import UI 框架 |
| REL-3 | 所有持久化写入具备事务性（SQLite 事务 + WAL），断电/强杀不产生半截状态 |
| REL-4 | 判定"进程仍存活"必须同时校验 PID 与进程启动时刻（防 PID 复用误判） |
| REL-5 | 崩溃风暴保护：单位时间重启超阈值强制 FATAL，绝不无限快速重启 |
| REL-6 | 睡眠唤醒、注销登录、外设变化后状态保持正确 |
| REL-7 | 连续运行 30 天无需人工干预（soak 为发布门槛） |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 单进程架构下 UI 层崩溃会连带所有被管进程，且无外部看门狗拉起 | 服务中断 | 这是"简单优先"的自觉取舍。缓解：监管核心零 UI 依赖并跑在独立队列；禁用强制解包等易 trap 写法；崩溃后下次启动自动接管仍存活的进程；崩溃计数进入事件日志以便发现 |
| 自研监管内核的边界情况不如 supervisor 久经考验 | 失管 | 状态机按 supervisor 语义 1:1 实现并做矩阵测试（A2）+ 故障注入 |
| 配置只在 SQLite 中，数据库损坏即全丢 | 配置丢失 | WAL + 事务；启动时完整性检查；每次变更后保留滚动 JSON 备份（最近 10 份）供一键恢复 |
| 同时运行 supervisord 与 Barback 管同一程序 | 端口冲突、双实例 | 导入强制 autostart=false + 明确引导；启动前检测同名命令是否已在运行并警告 |
| 功能膨胀（健康检查、依赖图、定时任务） | 违背克制原则 | §2.2 非目标清单作为拒绝依据，一律排入 v1.1+ |
