# Barback Windows 交互设计

日期：2026-09-30。状态：交互设计基线；实际实现及验证状态见[开发验证记录](implementation-status.md)。技术与行为约束以[总体设计](design.md)为准；本文规定用户实际看到的入口、信息和操作反馈。

2026-09-30 工作台修订已落地，当前入口和布局以[界面重设计](ui-redesign.md)为准：导航为程序/活动，设置位于侧栏底部；选中程序直接展示输出，Enter 打开详情；编辑内嵌并保护草稿；执行记录与系统事件合并到活动，历史没有启停控制。以下原设计中冲突的四标签、独立编辑入口和常驻多按钮示意已由该修订替代，进程、安全与存储语义仍适用。

## 1. Windows 桌面的入口分工

采用“完整主窗口 + 托盘快捷面板”。首次手动启动展示主窗口，以后从开始菜单/任务栏打开也恢复主窗口。登录自动启动只驻留，不自动弹窗打断工作。托盘可能被 Windows 收入溢出区，不能把配置、退出或错误恢复只放在托盘。

主窗口使用标准 Windows 标题栏、系统菜单、最小化、最大化、关闭和 Snap 行为。默认 1120×760 DIP，最小 800×560 DIP；低于可用工作区时自动缩小，正文滚动，不能让保存按钮落在屏幕外。记忆窗口尺寸与位置时记录显示器信息，显示器断开后把窗口移回可见工作区。

导航包括“程序”“执行历史”“事件”“设置”。“程序”页承担日常运行操作，编辑配置时进入该程序的独立编辑视图，避免把每次“停止”与配置的“禁用”混在一起。

```text
┌ Barback                                                    ─  □  × ┐
│ 程序       │ 程序                   [搜索…] [＋添加 ▾] [更多 ▾]    │
│ 执行历史   │ 8 个服务 · 5 运行 · 1 重试 · 1 失败                    │
│ 事件    1  │ [全部] [服务] [一次性命令]      分组：开发环境 ▾      │
│            ├───────────────────────────────────────────────────────┤
│            │ ● api-server    运行中        [停止] [重启] [日志] ⋯ │
│            │   PID 4821 · 12 分钟 · CPU 0.3% · 内存 48 MB          │
│            │ ◷ tunnel        3 秒后重试 2/3        [停止重试] ⋯   │
│            │ ⚠ worker        启动失败              [重试] [日志] │
│            │   找不到可执行文件                    [编辑配置]    │
│            │ ○ backup        上次成功 · 3.4 秒      [运行] [输出]│
│            ├───────────────────────────────────────────────────────┤
│ 设置       │ [启动全部服务] [停止全部…] [重启全部服务…]            │
└────────────┴───────────────────────────────────────────────────────┘
```

宽窗口可在右侧显示选中程序详情，窄窗口将详情放在同页的可返回视图；列表滚动位置与筛选保持。空状态只给“添加服务”“添加一次性命令”“迁移配置”，不显示一屏无效的批量按钮。加载失败与空列表必须有不同文案。

## 2. 托盘与快捷面板

图标表达正常/需要处理/停止中三类聚合状态，以形状和 tooltip 补充颜色。tooltip 例如“Barback：5 个运行，1 个需处理”。不做常驻闪烁或逐秒改图标。

| 操作 | 行为 |
| --- | --- |
| 单击/键盘激活图标 | 打开或关闭快捷面板 |
| 双击 | 幂等地打开主窗口；事件合并，避免单击面板残留 |
| 右键 / Shift+F10 | 标准上下文菜单：打开 Barback、添加、执行历史、事件、设置、退出 |
| 面板失焦 / Esc | 关闭面板，不影响运行任务 |
| 托盘图标不可见 | 用户仍可从开始菜单打开主窗口；首次隐藏时用应用内说明介绍通知区域溢出区 |
| Explorer 重启 | 恢复托盘图标；不重启或丢失被管进程 |

面板默认宽 440 DIP，高度最多工作区 70%，超出滚动；根据托盘所在显示器定位，处理缩放、任务栏自动隐藏与溢出区，不假设右下角坐标。失焦逻辑须识别本面板打开的菜单/对话框，避免点到“更多”就丢失操作。

```text
┌ Barback       5 运行 · 1 需处理        [打开主窗口] ┐
│ 搜索程序…                                         │
│ ● api-server      运行中       [停止] [重启] [日志]│
│ ◷ tunnel          重试 2/3     [停止重试]     [日志]│
│ ⚠ worker          启动失败     [重试]         [日志]│
│ 一次性命令                                        │
│ ✓ backup          上次成功     [运行]         [输出]│
│ [启动全部服务]                         [更多 ▾]    │
└───────────────────────────────────────────────────┘
```

面板总有搜索入口；行主动作和“更多”始终可发现，次级图标至少在键盘聚焦与悬停时出现。行单击选择，双击或 Enter 打开详情，不因选择触发启停。快捷面板不编辑配置；“编辑”跳到主窗口并定位。

Windows 通知区域应提供有用但克制的入口，不能要求用户固定图标才可操作；本设计据此保留完整主窗口。[微软通知区域规范](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area)

## 3. 运行操作与反馈

| 状态 | 主动作 | 补充信息/动作 |
| --- | --- | --- |
| 已停止 / 自行退出 | 启动 | 上次退出码、时间 |
| 启动中 | 停止 | “已启动，等待稳定 3 秒”，不显示“健康” |
| 运行中 | 停止 | 重启、日志；显示主 PID 指标口径 |
| 重试中 | 停止重试 | 剩余秒数、当前次数、上次失败原因 |
| 启动失败 / 风暴保护 | 重试 | 日志、编辑、清除失败；明确“自动重试已停止” |
| 停止中 | 立即强制终止… | 宽限期倒计时，禁止并行启动 |
| 清理失败 | 重试清理 | 明确还有未确认退出的进程，不显示“已停止” |
| 一次性命令未运行 | 运行 | 上次结果、输出、历史 |
| 一次性命令运行中 | 中止 | 运行时长、输出；再次运行禁用 |
| 中断 | 重新运行 | 提示上次结果未知，执行前再次确认可能的重复副作用 |

默认单服务启动、停止、重启无需重复确认；配置采用“立即终止 Job”时首次运行前在配置中确认停止风险，列表保留可见提示。额外“立即强制终止”按钮始终有确认，因为它跳过已约定的等待期。

“停止全部”列出服务数和一次性任务数，默认焦点为取消；“重启全部服务”说明只影响服务。确认对话框打开期间状态变化时，以提交时核心的最新状态重新计算并反馈，不对已经结束的 Run 再发动作。高频单项操作每次只发送一个有标识的请求，显示处理中并禁用重复按钮。

错误以“发生了什么 + 可执行的下一步”为基本结构。例如：

- “找不到 `C:\Tools\node.exe`。请选择新的可执行文件。”按钮：编辑配置。
- “程序要求管理员权限；Barback 以普通用户运行。”按钮：查看详情。不提供自动提权重试。
- “10 秒内没有完成停止，已强制终止进程树。”按钮：查看事件。
- “日志磁盘空间不足，部分输出未保存。程序仍在运行。”按钮：打开日志设置。

把技术错误码放进可展开详情/复制诊断，主要反馈不要只显示 HRESULT。失败提示保留到问题解决或用户关闭，不能只闪一个 Toast。

## 4. 配置编辑

```text
┌ ← 程序 / api-server                       日志   更多 ▾ ┐
│ 服务 · 运行中 · PID 4821                                │
│                                                        │
│ 基本信息    名称 [api-server]   分组 [开发环境 ▾]         │
│ 启动方式    [直接执行 ▾]                                │
│ 可执行文件  [C:\Tools\node.exe             ] [浏览…]     │
│ 参数        [C:\Projects\api\server.js      ] [删除]     │
│             [--port] [8080]                  [添加参数] │
│ 工作目录    [C:\Projects\api               ] [浏览…]     │
│ ▸ 环境变量  继承用户环境 · 2 个覆盖 · 1 个敏感值          │
│ 运行规则    ☑ 启用配置    ☑ 随 Barback 启动              │
│             自动重启 [仅非预期退出 ▾]                   │
│ ▸ 启动与重试  存活 5 秒 · 最多重试 3 次                  │
│ ▸ 停止方式    尝试 Ctrl+Break · 等待 10 秒               │
│ ▸ 日志与保留  UTF-8 · 10 MiB · 保留 3 份                 │
│ ▸ 备注                                                 │
├────────────────────────────────────────────────────────┤
│ 有未保存的更改          [放弃更改] [保存] [保存并重启]   │
└────────────────────────────────────────────────────────┘
```

表单布局：正文最大宽 880 DIP，24 DIP 边距；窄窗口标签移到输入框上方，固定底部保存区。高级设置最多一层折叠，摘要显示实际配置；错误自动展开，修复后保持展开。“偏离默认值”和“未保存”分开表达。

执行方式切换后只展示相关字段。把 PowerShell/cmd 命令文本放在明确的脚本编辑区域，不用一个模糊的“通过 Shell”开关。参数列表一个元素表示一个参数，可多行编辑；“复制可读命令”仅为展示，不把重新解析结果当作真实运行配置。检测到 `.cmd/.ps1` 时提示选择对应模式，需用户接受才转换草稿。

环境变量支持表格与多行文本粘贴。值默认字面量，敏感项以密码框显示、单独控制是否揭示；不自动复制全部秘密。“继承”“覆盖”“移除”三种来源明确。原始草稿必须保留空白和不完整输入；`Path`/`PATH` 冲突按行报告，错误中不含值。

| 保存场景 | 行为 |
| --- | --- |
| 没有修改 | 保存禁用 |
| 改名、分组、备注 | 保存即生效，不提示重启 |
| 改启动/环境/停止/日志等运行参数 | 可保存，现有 Run 不变；提示“下次启动生效” |
| 运行中服务选择保存并重启 | 先保存成功，再停止和启动；校验失败保持旧任务 |
| 已保存且有待生效配置 | 单独显示“立即重启”；有新草稿时合并为“保存并重启” |
| 正在运行的一次性命令 | 仅保存供下次使用，无保存并重跑按钮 |
| 禁用正在运行的配置 | 说明仍在运行；可另选“保存并停止” |
| 版本冲突 / 写库失败 | 保留草稿，展示差异或重试，不用旧快照覆盖新配置 |

切换程序、返回、关闭窗口时，草稿有修改则显示“保存 / 放弃 / 取消”。Esc 先关闭菜单/弹层或离开当前编辑步骤，不直接丢弃整个草稿。保存期间禁用再次提交，关闭请求等待结果；失败保留内容。校验失败聚焦首个错误，并显示错误总数；不得因失焦就执行重启。

复制默认生成新名称、新 ID，关闭 enabled/autostart，敏感值复制需要明确说明。删除确认写清会停止活动程序、删除配置和关联历史；默认仅清理应用拥有的输出文件，外部自定义日志不默认删除。

## 5. 日志、执行历史与事件

日志默认在主窗口程序详情中打开，可“在独立窗口打开”，同一个 Run/流复用窗口。日志页显示“跟随/暂停滚动”“搜索范围”“编码”“stdout/stderr”“在资源管理器中显示”“导出”。文件不存在时显示“尚无输出”；清理后显示“输出已清理”，不能混同读取失败。

用户滚动查看旧内容时暂停自动跟随并显示“有新输出”；点击“继续跟随”才滚到底部。搜索不抢输入焦点，不在每行输出时刷新整个文档；长行、无换行和乱码均不能阻塞 UI。隐藏日志页不停止采集。清屏只清显示缓存；“删除日志文件”是独立动作，运行中不允许直接删除活动文件，可选择“轮转并清理历史日志”。

执行历史为标准可排序表格：时间、程序、结果、耗时、退出码；可按程序/结果/日期筛选。双击或 Enter 打开本次输出，重跑使用**当前配置**并明确标注；原配置快照只用于查看。已删除程序的历史不会给可用的重跑按钮。未知退出码显示“未知”，超时/取消/中断使用不同文案。

事件页记录自动重启、清理、配置保存、恢复、日志故障等原因；与 stdout/stderr 输出分开。异常摘要点击后定位具体事件；展示时间使用本地时区，导出保留 UTC 与时区信息。

## 6. 关闭、退出和首次使用

第一次关闭主窗口时显示简短说明：“窗口关闭后，Barback 会继续运行。可从通知区域或开始菜单再次打开。”允许记住选择，并提供“关闭时退出应用”设置。未保存草稿确认优先于隐藏操作。

明确退出时，若有活动程序，显示“退出并停止 5 个服务和 1 个任务”；默认取消，可展开列表。用户确认后展示停止进度、剩余等待和“立即强制退出…”。清理期间不再接受新启动，但保持 UI 响应；确认后的取消只取消退出意图，已停止的程序不会自动重新启动。无任务时直接退出。

首次使用只引导必要概念：

1. 添加一个服务或一次性命令，选可执行文件并预览启动信息。
2. 告知“关闭窗口会继续运行；退出应用会停止被管程序”。
3. 登录启动默认关闭，在设置中自愿开启；在第一次需要系统通知时解释通知用途。

不在首次启动连弹多个权限/启用窗口。不把“Windows Service 安装”“自动提权”作为推荐路线。

## 7. 通知与设置

通知只传达需要处理的信息，点击打开相关程序/Run。首版没有通知内直接启停按钮，避免旧通知作用到新一轮进程。

| 事件 | 默认通知 |
| --- | --- |
| 重试耗尽 / 风暴保护 | 开启；按程序 + 类型去抖 10 分钟；正文含原因摘要 |
| 正在自动重启 | 关闭（事件页保留），可在设置开启 |
| 一次性命令失败/超时 | 开启；失败正文含十进制与十六进制退出码；不做去抖 |
| 一次性命令成功 | 关闭，可开启；当前正在查看该 Run 时不重复打扰 |
| 无法确认子进程已清理 | 开启（同时写入“清理未确认”事件） |
| 日志不完整（磁盘满等）/ 应用中断恢复 | 开启，**全局按类型**聚合去抖 10 分钟，不逐程序轰炸 |
| 用户主动强制停止 / 宽限期到期的强制终止 | 关闭，只记录事件 |
| 应用正在退出期间的任何事件 | 关闭 |

通知标题是程序名（无程序时为 “Barback”），正文说明发生了什么；一次性命令失败/超时的通知为只通知、不写入第二条事件（`RunEnded` 已记录）。

尊重 Windows 勿扰、系统关闭通知和组织策略；发送成功不意味着用户看到了。应用内事件与错误横幅是可靠记录。通知注册失败仅影响通知，设置中显示原因和系统入口，不阻止运行。

设置分为“常规”“运行环境”“通知”“存储与诊断”“关于”：包括关闭行为、登录启动实际状态、主题/密度/语言、环境刷新、保留预算、备份恢复和主动检查更新。系统不允许启用登录启动时显示“已被 Windows 禁用”，按钮打开“启动应用”设置，不呈现一个虚假的开启开关。

## 8. 键盘、无障碍与视觉

使用 WPF 标准控件与 UI Automation。系统标题栏、可见焦点、Tab 顺序、文字缩放、高对比度和 Narrator 都是发布要求，不以 Fluent 主题截图代替验收。微软建议优先使用已有无障碍支持的标准控件，并提供明确焦点和非文本元素名称。[Windows 无障碍最佳实践](https://learn.microsoft.com/en-us/windows/win32/winauto/accessibility-best-practices)

| 快捷键 | 语义 |
| --- | --- |
| Ctrl+F | 聚焦当前页面搜索 |
| Ctrl+N / Ctrl+Shift+N | 新建服务 / 一次性命令 |
| Ctrl+S | 保存当前编辑草稿 |
| Ctrl+D | 程序列表上下文中复制配置；文本编辑器不拦截默认按键 |
| Delete | 仅列表焦点下删除配置并确认；文本框保持文本删除 |
| Enter / Space | 激活当前聚焦控件；列表 Enter 打开详情，绝不隐式启停 |
| Tab / Shift+Tab、方向键 | 原生焦点移动与列表选择 |
| Shift+F10 | 当前对象上下文菜单 |
| Esc | 关闭最上层菜单/面板；编辑草稿受未保存保护 |
| Alt+F4 | 标准关闭当前窗口，遵循关闭行为设置 |

不注册全局快捷键，不把 macOS 的 Command 键机械替换成 Ctrl 后占用常见文本操作。主操作可以通过焦点按钮执行，不要求记住容易误触的启停组合键。

状态同时包含图标、文字和颜色；“运行中”的绿色保持低强调，失败原因可读且带动作。图标按钮有可访问名称与 tooltip，重要操作不只在 hover 出现。读屏播报关键状态改变，但不逐秒播报计时、CPU 或日志输出。

首版 zh-Hans 与 en-US 资源分离，测试长英文和中文路径；状态枚举/错误码不能直接作为用户文案。支持 100/125/150/200% DPI、系统文字放大、深浅色、高对比度和减少动画。布局尺寸使用 DIP，托盘定位需要正确处理物理像素换算；远程桌面切换 DPI 后重新布局。
