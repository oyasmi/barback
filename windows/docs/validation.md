# Barback Windows 实施与验收计划

日期：2026-09-30。**这里是待执行的验证计划，不是已通过的测试报告。** 原设计交付只迁移 macOS 目录并交付设计，Windows 实现依据[总体设计](design.md)与[交互设计](interaction.md)推进。

## 1. 阶段与完成条件

| 阶段 | 交付 | 必须满足的退出条件 |
| --- | --- | --- |
| M0 技术可行性 | 最小 WPF/托盘/MSIX 原型、Job/ConsoleHost/日志探针、技术验证记录 | 下列四项高风险关卡全部有真实 Windows 证据；失败需先修订设计 |
| M1 核心监管 | 项目结构、领域模型、两类 reducer、SQLite、受限启动/停止、测试子程序 | 状态矩阵、幂等、Job 树清理、配置事务测试通过 |
| M2 日志与恢复 | 有界采集、轮转、编码、历史、故障恢复、诊断包 | 高输出/磁盘满/崩溃/损坏库测试通过，无无限内存增长 |
| M3 完整交互 | 主窗口、托盘、编辑、历史、事件、通知、登录项、INI 预览 | 用户路径、键盘、Narrator、DPI、草稿保护验收通过 |
| M4 发布候选 | x64/ARM64 签名安装包、升级/卸载/迁移、支持矩阵和性能报告 | 完成所有 P0 用例，干净机器安装与长时间运行通过 |

M0 是验证工作，不先制作完整产品界面。四个发布阻断关卡：

1. **Job 创建与终止**：创建前、创建后未恢复、宿主握手、目标刚运行、根进程已退子进程仍存活等时点结束 App，证明无未归属进程和重复运行；嵌套 Job/禁止 breakaway 失败时明确报错。
2. **控制台停止**：在 Windows Console Host 与 Windows Terminal 默认终端环境下，隐藏宿主无可见闪窗；两个服务同时运行，停止一个不向另一个发送 Ctrl+Break；记录支持与不支持优雅清理的实际目标。
3. **MSIX 真实环境**：签名安装、开始菜单激活、通知点击、任务管理器禁用登录项、用户数据路径、卸载清理行为；Node/Python/dotnet/PowerShell 的配置与缓存未出现不可接受的虚拟化差异。
4. **桌面适配**：WPF Fluent 原型在 Narrator、高对比、中文输入、200% DPI 与混合缩放屏幕上可完整操作；Explorer 重启恢复托盘。

不以 `dotnet build` 成功证明这些行为可行。关卡失败需记录触发条件、系统版本、替代方案与功能影响，再更新设计。例如控制台方案失败时不能仍保留“优雅停止已支持”的 UI 文案。

## 2. 测试环境与工具

纯 reducer 使用 xUnit、可注入时间和虚拟 Effects 执行器；用真实 Windows 子进程覆盖 Win32 互操作。`Barback.TestChild` 至少支持：延迟退出、DWORD 退出码、处理/忽略 Ctrl+Break、派生多层后代、根提前退出、持续输出、无换行/超长行、分块多字节、保持输出句柄、分配内存和尝试 breakaway。另准备小型 `.cmd`、`.ps1` 和参数回显用例。

自动化测试只在每次运行专属的临时目录、命名管道和 Job 内操作；按持有句柄清理，绝不按进程名称批量杀系统上的 node/python。故障注入覆盖创建、存储、I/O、注册回调各边界；保留 RunId 和事件序列便于重现。

| 环境 | 用途 |
| --- | --- |
| Windows 11 x64，标准用户，干净配置 | 核心自动化和安装验收 |
| Windows 11 ARM64，原生进程 | ARM64 SQLite/互操作/宿主/通知/安装验证，模拟构建不能替代 |
| 本次发布仍支持的最早与最新 Windows 11 版本 | API 与壳层行为回归，记录 edition/build/补丁 |
| 非英文用户名、路径含空格/中文、长路径 | 参数、路径、日志与导入 |
| 双屏不同 DPI、仅一屏、任务栏自动隐藏、RDP | 托盘定位、窗口恢复、焦点和缩放 |
| 默认 Windows Terminal / Windows Console Host | 控制台创建与停止差异 |
| 标准终端 / MSIX / CI 的父 Job 环境 | 嵌套 Job 与权限行为 |

## 3. 核心验收矩阵

所有 W 编号均为发布 P0；P0 表示失败时不发布相关首版能力，不表示已经通过。

| 编号 | 场景 | 可核查结果 |
| --- | --- | --- |
| W01 | 服务正常启停、手动重启 | 一个程序最多一个 Run，旧 Job 清空后新 PID 才启动，stop 不触发自动重启 |
| W02 | autorestart 三策略 × 预期/非预期退出 × 门槛内外 | 与状态表一致，门槛内退出码 0 仍计启动失败 |
| W03 | 初始失败 + 3 次重试 | 共最多 4 次启动尝试，退避 1/2/4 秒；第四次失败进入 FATAL |
| W04 | 600 秒内自动重启风暴 | 最多允许 10 次自动重启，第 11 次被阻止；关闭重开 App 不清除 FATAL |
| W05 | 多层树、根先退、子进程另开控制台 | 保留树成员归属，最终整 Job 清空；不依赖控制事件清理所有后代 |
| W06 | Ctrl+Break 响应/忽略/宿主退出 | 正常响应可先自行清理；忽略时按期限终止；宿主故障不留下目标 |
| W07 | 创建各阶段结束 App，循环 100 次 | 包括 suspended 阶段，无孤儿/悬挂进程；下次运行记录为中断，无重复启动 |
| W08 | 持续点击启动/停止/重启、计时器迟到 | 过期 Generation 无效，不停止新 Run，不重复结束记录 |
| W09 | DWORD 高位退出码、259、PID 复用 | 展示十六进制完整代码；存活依据句柄；绝不影响无关 PID |
| W10 | 一次性成功/失败/超时/取消及竞态 | 正确终态，只执行一次；停止中不能启动；超时和取消不被随后代码 0 覆盖 |
| W11 | App 崩溃后恢复 | Interrupted、未知码；仅符合恢复规则的服务启动；已手动停/STOPPING/FATAL 不恢复；一次性不重跑 |
| W12 | 锁屏、RDP 断开、睡眠/唤醒、时钟回拨 | 不误判退出，不爆发补重试；一次性超时按睡眠包含规则触发 |
| W13 | 明确退出、注销、关机 | 无新启动，按预算停止；Job 清理兜底；下次不把中断记录标成功 |
| W14 | 非英文路径、引号、空参数、末尾反斜线 | 目标回显参数逐个等于用户输入，lpApplicationName 明确 |
| W15 | cmd 元字符、npm.cmd、PowerShell 5.1/7、缺失引擎 | 显式模式正确；直接模式不执行管道；不自动 bypass 执行策略或加载 Profile |
| W16 | PATH 差异、变量大小写、删除继承变量 | 终端临时变量不被隐式依赖；Path/PATH 报冲突；刷新只对新 Run 生效 |
| W17 | INI 含 POSIX 命令、未知字段、重名、恶意插值 | 仅解析预览，无执行/联网/文件 include；禁用草稿，autostart=false，不静默覆盖 |
| W18 | 目标需管理员、外部代理创建任务、breakaway | 提供明确不支持/启动错误，无假装成功或无 Job 降级 |
| W19 | 同一用户第二实例、不同会话、Explorer 重启 | 同会话只激活；不同会话不重复监管；托盘恢复不影响进程 |
| W20 | 目标/宿主句柄继承检查 | 无 Job/控制管道句柄泄漏，输出端正确关闭，结束后日志 EOF 可达 |

## 4. 数据与日志验收

| 编号 | 场景 | 可核查结果 |
| --- | --- | --- |
| W21 | stdout/stderr 同时大量输出、长时间无换行 | 同时排空，不卡死目标/UI；缓存有界，长行分块 |
| W22 | 队列溢出、磁盘满/只读、文件被锁 | 明确日志不完整及丢弃量；监管继续；恢复写入有缺口标记 |
| W23 | 活动轮转、查看器打开、程序重命名 | 文件数和大小受控，查看器恢复读取，无多个 Run 写同一文件 |
| W24 | UTF-8 拆字、UTF-16LE、代码页 936、非法字节 | 增量解码稳定；原始字节可导出；无乱码导致的 UI 崩溃 |
| W25 | 全局预算、50 次历史、清理时仍运行 | 保留策略正确，活动文件不误删；累计次数不倒退，输出已清理可辨认 |
| W26 | 保存期间崩溃/数据库锁/磁盘满 | 原子提交；不丢草稿或假成功；现有任务仍可停止 |
| W27 | WAL 有未合并数据时备份、迁移中断、损坏库 | 备份可恢复；保留损坏源；恢复默认不启动；高 schema 拒绝旧版写入 |
| W28 | sensitive 变量、诊断导出、另账户恢复 | 磁盘中非明文；默认诊断无变量值/完整参数/业务输出；DPAPI 不可解时要求重新输入 |
| W29 | 非法管道请求、超长消息、旧通知激活 | 拒绝异常输入；只导航页面；不能通过激活接口启动任意命令 |

| W30 | 首次启动→添加服务→运行→日志→停止 | 全程主窗口可达，托盘两次点击内完成常用单项操作 |

| W40 | 真实 x64/ARM64 包上重复 W01/W05/W06/W21/W37/W38 | 对两架构分别留证据，不能仅有交叉编译日志 |

## 6. 性能与稳定性预算

这些是待测目标，禁止写进产品介绍当作已测指标。记录 CPU、内存口径、硬件、系统、构建模式和样本；使用 Release 包，排除被管业务程序自身的资源。

| 项目 | 初始预算与测量方法 |
| --- | --- |
| 隐藏空闲 | 10 个无输出服务稳定后，10 分钟平均 App + ConsoleHost CPU < 单逻辑核的 1%；不做逐程序定时存活轮询 |
| 内存 | App 私有字节 < 150 MiB；每个 .NET ConsoleHost 初始预算 < 40 MiB；合计预算如实计入，不只报告 UI 进程 |
| 启动/操作 | 本地 SSD、无任务冷启动主窗口 p95 < 2 秒；按钮请求反馈 p95 < 100 ms，实际进程启动时间另列 |
| 大列表 | 100 个配置项、20 个运行程序，搜索/滚动输入反馈 p95 < 100 ms；使用虚拟化 |
| 日志 | 合计 10 MiB/s 持续 10 分钟，核心仍接受停止；正常磁盘预算内无丢失，过载时丢弃可见且内存有界 |
| 树清理 | 20 个程序、每个 3 层后代，正常退出最多 30 秒全局预算；超出必须记录原因，不谎报清理完成 |
| 稳定性 | 72 小时混合启停/随机失败/轮转，无持续私有字节或句柄增长；发布前再做 7 天日常负载运行 |

超预算先分析是否来自宿主、日志或 UI。优化不得删除 Job 归属保护或隐瞒日志缺失；必要时调整 ConsoleHost 实现并重新跑 M0，不能为追求 macOS 的近零日志开销退回不可靠轮转。

## 7. CI 与发布证据

本次仓库迁移只调整已有 macOS CI 的工作目录，尚未加入不存在的 Windows 构建任务。实现 M1 后新增独立 Windows workflow，路径变化覆盖 `windows/**` 与相关 workflow：

1. Windows runner 安装固定 .NET SDK，锁定恢复并构建 Release；运行核心、存储和真实进程测试。
2. 上传 TRX、失败时的脱敏事件与测试子进程清理报告；所有进程测试 finally 清理独立 Job。
3. 在交互桌面机器完成 UI/安装/通知/登录任务验证；无交互 CI session 不能替代此步骤。
4. x64 与 ARM64 分别出包；ARM64 实机 smoke 为发布条件。证书来自受保护的发布环境，不给普通 PR 作业签名能力。
5. 记录包版本/哈希、依赖、SBOM、系统支持矩阵、已知限制、schema 版本与备份恢复结果。

最终验收报告逐项填写 W01–W40 的“通过/失败/阻塞”、环境、证据路径和日期。没有证据的项目保留待验证，不以文档设计完成代替 Windows 产品完成。
