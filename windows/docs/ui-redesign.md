# Barback Windows 工作台设计与实现

日期：2026-09-30。状态：推荐工作台已实现为原生 WPF 界面。交互预览使用虚构程序与输出，不启动真实进程。本文修订 `interaction.md` 的界面入口与布局；核心进程、安全、存储语义仍遵循原设计。原始问题分析与轻量列表对照保留为设计依据。

## 产品方向

Barback 是一个高频使用的本地程序管理工具。用户打开它，通常只想确认程序是否在运行、启动或停止一个程序、查看输出、处理失败。界面应当让这些事情一眼可见、一步可做；新建和编辑配置是次一级任务，诊断与迁移是低频任务。

推荐“工作台”：安静的 Windows Fluent 外壳、紧凑的程序列表、选中后直接出现的输出与详情。另提供“轻量列表”作为设计对照：同样的导航与操作规则，简要输出在对应行下方展开，可再打开完整详情，更适合少量程序和频繁启停。主窗口推荐采用工作台，托盘采用轻量列表的行结构，不另造一套规则。

## 当前问题及依据

1. `MainWindow.cs/BuildPrograms` 把 12 个单项与全局动作常驻在列表下方。选中对象不明确，启动、停止、强制终止和删除视觉权重相同；空列表仍占据大量操作空间。
2. 名称、分组、状态、PID、配置版本、详情等宽分列。主要内容反而稀疏，内部实现信息占据首屏，名称和错误原因缺乏层级。
3. 执行历史顶部的 `Start` 实际只重跑当前仍存在的一次性命令，却复用“启动 / 运行”文案；结果筛选直接枚举 `Phase`，又把运行状态和历史结果混在一起。这不是增加解释文字就能解决的，需要改变操作归属与命名。
4. 当前表格双击进入编辑，日常查看输出却要先选中再寻找底部按钮。选择、检查和修改的成本分配不合理。
5. 仓库现有交互文档已提出上下文操作、空状态和自适应详情，但实现在这些方面仍是初始控件拼接。
6. macOS 的 `StatusStyle.primaryAction`、`ProgramRowView` 已有可复用原则：状态决定主动作；正常运行低强调，失败显露原因；辅助信息渐进展开。Windows 沿用这些语义，外观遵守 Windows 的字体、标题栏、键盘和窗口行为。

## 信息架构与入口

```text
Barback
├─ 程序                        默认首页、所有实时控制
│  ├─ 全部 / 需要处理 / 分组    视图过滤，不是另一个工作区
│  └─ 选中程序
│     ├─ 输出                  默认详情；一次性命令称本次输出
│     ├─ 配置                  只读摘要 → 编辑配置
│     └─ 记录                  该程序的执行记录
├─ 活动                        回顾、审计、排障
│  ├─ 执行记录                 已结束的 Run；没有停止按钮
│  └─ 系统事件                 Barback 的决策与故障；不混入 stdout/stderr
└─ 设置                        左侧底部，低频
   ├─ 常规与外观
   ├─ 运行环境
   ├─ 通知
   └─ 数据与诊断（含迁移 INI、备份、恢复、关于）
```

只保留两个顶层日常入口，不把四个功能都做成同级大标签。详情中的“输出 / 配置 / 记录”只切换同一个程序的视角，切换不会丢失选中对象。系统事件和执行记录在活动内仍分开，避免把两类数据强行合并成一个时间流。

## 主窗口布局

- 原生标题栏保留系统菜单、拖动、Snap、最小化、最大化和关闭。浅色采用暖灰外壳、白色内容面；深色使用对应不透明表面。实现时可在支持的系统上使用系统背景材质，Windows 10 与高对比模式有可靠回退。
- 左侧 176–200 DIP 导航；顶部是程序与活动，下方是“需要处理”与分组，底部为设置。分组是现有 `Group` 的视图，切换分组即回到程序页，不表示新增项目或目录模型。
- 主内容顶部：页名、搜索、一个“添加”入口。添加菜单区分“常驻服务”和“一次性命令”，各有一句用途说明。INI 迁移放在数据设置与首次空状态。
- 标题下只用一行汇总：`2 个运行 · 1 个重试中 · 1 个需要处理`。只显示非零异常项，不放大型数字卡片；汇总来自完整快照，分组范围另注明。
- 列表以名称和状态为主轴，按分组组织，组内保持稳定名称顺序。每行约 64–72 DIP，次行给短命令或关键原因；CPU、内存、PID 和配置版本进入详情。不会随每次状态更新自动重新排序。
- 每行常驻一个状态主动作和一个“更多”。按钮在行内明确绑定对象；选中仅查看，点击名称、Enter、双击均不隐式启停。
- 右侧约 320–400 DIP 为选中程序详情。默认直接显示输出；标题下显示状态、运行时长和主 PID 指标，运行服务可见“重启”。停止仍由行主动作承担，避免再叠一排重复按钮。
- 全局批量操作在列表标题的“更多”中，明确叫“启动全部已启用服务”“停止所有运行程序…”“重启全部已启用服务…”。分组操作放在组标题菜单；搜索结果绝不悄悄改变全局操作范围。多选时显示上下文工具栏替代常规工具栏，写明服务与任务数量，不无限增加常驻按钮。

## 操作随状态变化

| 对象与状态 | 行主动作 | 详情/更多 | 反馈 |
| --- | --- | --- | --- |
| 服务已停止、已退出 | 启动 | 编辑、复制、删除 | 点击后立即显示启动中 |
| 服务启动中 | 停止 | 输出 | 说明正在等待稳定期，不宣称健康 |
| 服务运行中 | 停止 | 重启、输出、编辑 | 停止后等待宽限期，无重复请求 |
| 服务重试中 | 停止重试 | 输出、失败原因、编辑 | 显示剩余时间与次数 |
| 服务启动失败/风暴保护 | 重试 | 编辑、输出、清除失败状态 | 保留具体失败原因，说明自动重试已停止 |
| 停止中、等待宽限期 | 等待停止（禁用） | 可用时显示“立即强制终止…” | 倒计时，超时按配置升级；强制操作需确认 |
| 清理失败 | 重试清理 | 诊断详情 | 说明尚有未确认退出的进程，不给启动 |
| 一次性命令未执行或已结束 | 运行 | 上次输出、记录、编辑 | 运行前确认按配置执行 |
| 一次性命令执行中 | 中止 | 本次输出 | 不给并行重跑；显示正在执行 |
| 一次性命令上次中断 | 重新运行… | 原记录、输出 | 明确上次结果未知，确认重复副作用 |
| 配置已禁用且未活动 | 无可用启停主动作 | 编辑配置、启用配置 | 禁用不等于停止；启用不隐式运行 |

停止采用中性按钮；启动/运行采用低强度强调，只有当前任务的重要动作使用实心强调按钮。红色用于明确失败与危险操作，不把常见“停止”做成整行红色。当前失败行展示一句原因及“编辑配置”下一步，历史失败不会让已恢复服务永久挂警告。

“需要处理”仅聚合当前失败、清理失败、日志故障和恢复待处理等仍然有效的问题；成功重跑、修复或处理完成后消除当前标记，原始历史仍然保留。自动重试中的任务属于过渡态，单独标橙色，不都算成失败。

## 关键流程

### 看状态、启停、看日志

打开后保持上次搜索、分组、选中项和位置。点击该行主动作就执行；选中名称就能看输出。重启在所选服务详情中，不要求离开当前日志。操作期间仅禁用该对象不兼容的操作，其他程序照常使用。默认单项启动、停止、重启不确认；强制终止、删除、批量停止和退出采用明确确认。

### 查看历史与重跑

活动的执行记录展示时间、程序、结果、耗时与退出码。结果仅用成功、失败、超时、已中止、已中断/未知等历史结果，不使用“运行中 / 已停止”作为成功与失败的替代。正在运行的条目留在程序页，其实时输出直接可见。

选择历史记录后打开本次输出及当次配置快照，只读。一次性命令才提供“用当前配置重新运行…”；确认同时列明程序名、所选记录时间和当前配置版本，解释会创建新的执行。原程序已删除、禁用或当前在执行时按钮不可用并说明原因。服务的历史不会出现“运行”或“停止”；提供“定位当前程序”。

### 编辑与保存

详情“配置”先展示摘要，再点击“编辑配置”。编辑占据主内容区，保留导航位置，避免每次弹新窗。先展示名称、分组、执行模式、文件、参数、工作目录；环境变量、启动重试、停止、日志等用一层折叠和实际值摘要。

底部保存区始终在窗口可见范围内：无改动时不制造可点保存按钮；修改后提供“取消”“保存”，运行中服务修改运行参数时增加“保存并重启”。默认保存仅影响下次运行，当前输出页显示“配置已更新，下次启动生效”。改名或分组不要求重启；一次性命令绝不提供保存并重跑。字段错误原地展示、自动展开相关区域、焦点落到首个错误。切换对象或关闭时保护草稿。

添加先选择类型，服务解释为“持续运行，可自动重启”，一次性命令解释为“按需执行，保留每次结果”。创建时不自动执行。导入先展示转换预览、失败字段与冲突，保存后保持禁用，不将 macOS 的 POSIX 配置当成可直接运行的 Windows 配置。

### 输出

日志区域采用等宽字体，不强制漆黑终端风格；stdout/stderr 文本和标记可区分。常驻仅“搜索已加载输出”“跟随”；编码、流选择、导出、资源管理器与独立窗口放在输出菜单。查看旧内容时暂停跟随并提示有新输出，继续跟随由用户决定。输入搜索时保持焦点。

输出为空、读取失败、已被清理、采集存在缺口、记录仍在执行要有不同状态。运行配置版本与当前配置版本不一致时显示待生效提示。PID、CPU 和内存标明“主进程”；样本不可用显示未知，不画看似实时的假曲线。详情不见时仍持续采集，UI 更新批处理，不逐行重绘整个页面。

### 托盘与退出

托盘快捷面板约 440 DIP，仅保留搜索、名称/状态、状态主动作、更多、打开主窗口。常用启停无需启动完整工作台。选择输出可打开独立日志或定位工作台，编辑只能去主窗口。同一套状态与文案用于两个入口。

关闭主窗口默认后台继续运行；首次以轻提示解释，设置可改变。明确退出放在应用菜单/托盘菜单，不占据内容区一个巨大常驻按钮。存在活动程序时显示“退出并停止 N 个服务和 M 个任务”，列出影响范围与停止进度；取消退出不会自动启动已经停止的程序。

## 视觉与原生感

- 字体：系统 Segoe UI Variable / Segoe UI，中文使用系统回退；普通文本 14 DIP，次级文本 12 DIP，页名约 24 DIP，避免大面积粗体。输出 Cascadia Code / Consolas。
- 间距：4 DIP 基础步长，页面 24 DIP，内容组 16–24 DIP；按钮通常约 32 DIP 高、4–6 DIP 圆角。内容面 8 DIP 圆角，菜单与弹层有轻阴影，列表不做一张程序一张大卡片。
- 色彩：系统强调色仅用于选中标记、启动与关键确认；健康状态用小绿点和文字，失败用图标、短原因和低强度背景。状态不能只靠颜色识别。
- 默认随系统浅/深色；高对比模式优先系统颜色和边界，不依赖半透明。尊重减少动画，不循环闪烁；不让颜色主题切换影响日志内容和操作。
- 使用原生 WPF 控件、UI Automation 与上下文菜单，保留可见焦点、键盘列表选择、Alt+F4、窗口边缘缩放和系统缩放。原生感包含这些行为，不仅是圆角和材质。

## 自适应与验收

目标主窗口 1120×760 DIP。约 1060 DIP 以上采用侧栏+列表+详情；较窄时收缩导航，详情进入可返回的同页视图，不把三栏一起挤小。保持筛选与列表位置；800×560 及有效文字放大环境中也能看到主动作和保存区。交互稿为便于在对话内体验采用竖向堆叠，真实 WPF 的窄窗应采用单页钻取。

至少验证：100/125/150/200% DPI，系统文字放大，浅色、深色、高对比，键盘全流程、Narrator，长中文/英文名称与路径，空数据、加载中、读取失败、50/200 个程序，频繁状态更新，运行中配置已修改，清理失败，日志超长行与无换行，多屏与窗口移回可见区域。列表必须虚拟化，刷新不会丢失选中和焦点。

快捷键沿用 Ctrl+F 搜索、Ctrl+N 添加服务、Ctrl+Shift+N 添加命令、Ctrl+S 保存、Shift+F10 菜单、Esc 关闭顶层弹层；Enter 打开详情，绝不拿它当隐式启动。编辑文本时尊重标准文本快捷键。

验收的高频任务目标：程序启停 1 次点击、打开对应输出 1 次点击、重启所选服务 1 次点击、进入编辑 2 次点击。历史重跑有明确配置与新 Run 提示；空列表不出现不可用批量操作。不能用删除事件或“清除失败”伪装成问题已解决。

## 落地次序

1. 先改结构和语义：程序/活动导航、上下文主动作、清除底部按钮墙、历史操作正确命名与结果筛选；保持 Supervisor API 与进程行为。
2. 将界面从大量代码动态拼接整理为 XAML 视图、资源字典与视图模型，启用并验证 WPF Fluent 主题，抽出共享状态呈现与可执行动作解析。主窗口和托盘复用解析，按钮的可用性必须再次受最新核心状态保护。
3. 完成列表/详情与内嵌输出、编辑草稿导航、托盘、空状态和失败恢复。
4. 验证性能、DPI、Windows 10 回退和无障碍，再做材质与动效。采用 .NET 10 当前可用的 WPF Fluent 能力，不为外观更换进程核心或把桌面应用改成网页壳。

## 实现与验证

- `MainWindow.xaml`、`Resources/Workbench.xaml` 使用官方 WPF Fluent 原生控件，保留系统标题栏、窗口缩放和 UI Automation。`WorkbenchTheme` 提供随系统、浅色、深色与高对比系统颜色回退。
- `ProgramRow` 在状态更新时保留实例；程序列表开启分组虚拟化与回收。`ProgramActionPolicy` 同时用于主窗口与托盘，并在执行前重新读取核心状态。运行中禁用仍可停止，停止/清理阶段不能再启动，清理失败只提供重试清理。
- 输出默认内嵌；复用 `LogView` 的独立窗口保留有界尾随、双流、轮转识别、增量解码、磁盘搜索、原始字节导出。切换程序和缺失输出流会清理旧内容。
- `EditorView` 复用于内嵌与独立编辑器。固定保存栏、非法草稿保留、字段定位、保存冲突、敏感密码框及离开前保存/丢弃/取消保护均保留。仅修改名称/分组/备注不会误报启动参数待生效。
- 核心快照新增可选 `RunConfig`，供界面比较当前配置与本次运行参数、使用本次输出编码；不改 reducer 或进程控制协议。
- Windows 10 x64：64 项核心、13 项存储、12 项 Windows 进程测试通过；28 项原生 WPF 控件回归通过，真实控件截图检查覆盖浅色、深色、失败、活动、设置、托盘、800×560 列表/详情/编辑保存区。x64 与 ARM64 Release 构建通过，0 警告、0 错误；ARM64 仅交叉构建。
- 可重复执行 `./scripts/test-ui.ps1`。它创建专属数据库、模拟进程宿主和虚构输出，不读取用户数据、不注册通知、不执行真实命令。截图与检查结果保存在 `artifacts/ui-check/<时间>/`。

实现边界：原数据库不存储历史执行的完整配置及编码快照。历史页明确显示当前配置并保留原执行版本；历史日志按现存配置编码解码，已删除配置按 UTF-8 解码，原始字节导出不受影响。混合 DPI、Narrator、高对比系统切换、Explorer 重启、Windows 11、ARM64 实机及签名安装仍须完整桌面验收；自动化控件回归不能替代这些环境验证。
